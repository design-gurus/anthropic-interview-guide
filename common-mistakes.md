# Common mistakes in the Anthropic interview

The mistakes that candidates report most often in the Anthropic loop concern preparation for the wrong test. Candidates practice algorithm puzzles and meet a staged build. They study machine learning theory and meet a queuing problem. They rehearse polished stories for a round that rewards plain honesty. This page lists ten such mistakes and what to do instead.

## The ten mistakes

| # | Mistake | Stage | What to do instead |
|---|---|---|---|
| 1 | A generic "Why Anthropic?" answer | Application | Name one specific thing and connect it to your work |
| 2 | Following outdated advice on AI assistance | All stages | Read the current candidate guidance for each stage |
| 3 | Preparing only algorithm puzzles | Coding | Practice builds that you extend three times |
| 4 | Fitting the code to the first requirement | Coding | Write small functions that accept an addition |
| 5 | Improving the code before it passes | Coding | Finish the simple version of each level first |
| 6 | Studying machine learning theory for the design round | System design | Study queues, batching, routing, and failover |
| 7 | Applying a memorized architecture | System design | Start from the stated numbers and constraints |
| 8 | Agreeing with everything | Values | Prepare one specific, reasoned disagreement |
| 9 | Telling stories with no faults in them | Values | Include what you got wrong and what changed |
| 10 | Presenting a project you did not lead | Project review | Choose a project in which you made the decisions |

## Application and rules

**1. A generic "Why Anthropic?" answer.** The written field is required on most postings, and it is read. "I am passionate about AI" is true of every applicant. An answer of fewer than 100 words in a field that suggests 200 to 400 is reported to look like low interest.

**2. Following outdated advice on AI assistance.** Sources report that Anthropic changed its policy, and older articles still say that no AI assistance is allowed. The reported rule now differs by stage. See [Interview process](interview-process.md).

## Coding mistakes

**3. Preparing only algorithm puzzles.** Reported problems are practical tasks that grow. Pattern recognition on puzzle problems is reported not to be what is scored.

**4. Fitting the code to the first requirement.** Code that is fitted too closely to the first requirement must be rewritten when the second arrives. The rewrite costs both time and score.

**5. Improving the code before it passes.** Some versions lock the next level until the current tests pass. Candidates report running out of time more often than being stuck.

## System design mistakes

**6. Studying machine learning theory.** The design round does not ask how the model works inside. Sources state that nothing in a strong batching answer requires knowledge of how a transformer works. A transformer is the neural network design behind large language models.

**7. Applying a memorized architecture.** Questions are reported to be novel and close to the company's own work. A design copied from a well-known question does not fit them. Raise the failure cases before the interviewer asks, because reliability carries extra weight in this round.

## Values and project mistakes

**8. Agreeing with everything.** Uncritical enthusiasm suggests that you have not considered the risks. The reported question "Do you have any critique of Anthropic's direction?" expects a real answer.

**9. Telling stories with no faults in them.** Sources report that an answer that makes you sound faultless is received worse than one that names a real mistake. A rehearsed answer also sounds emotionally flat.

**10. Presenting a project you did not lead.** In the technical project review, interviewers are reported to keep asking until they reach the limit of your involvement. Prepare one project in depth, not three in outline.
